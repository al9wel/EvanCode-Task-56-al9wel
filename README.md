# نظام «وصّل» لإدارة طلبات التوصيل
**مهمة التوظيف رقم #56 — إيفان كود (Evan Code)**

تطبيق ويب عربي متكامل من اليمين لليسار (`RTL`) يحاكي نظام متابعة وإدارة طلبات شركة «وصّل» للتوصيل، تم بناؤه بهندسة نظيفة قائمة على الميزات (**Feature-Based Clean Architecture**) مع تركيز عالٍ على سرعة الاستجابة، وضوح الكود، وتجربة المستخدم على شاشات سطح المكتب والجوال.

---

## نظرة عامة (Overview)
يوفر التطبيق صفحة تعريفية للمشروع تليها لوحة تحكم تفاعلية تضم:
- **لوحة الإحصائيات الرئيسية (`/dashboard/main`):** مؤشرات الأداء اليومية، رسوم بيانية تفاعلية لحركة التوصيل وتوزيع الحالات والذروة الأسبوعية، قائمة متحركة لأحدث الطلبات الواردة، وسجل النشاط الميداني للمندوبين.
- **إدارة الطلبات (`/dashboard/orders`):** عرض 24 طلباً تجريبياً واقعياً بكامل تفاصيلها (رقم الطلب، اسم الزبون، المنتجات، المبلغ، التاريخ، والحالة)، مع البحث المباشر باسم الزبون، الترتيب حسب التاريخ أو المبلغ، الفلترة حسب الحالة، الترقيم (`Pagination`)، ونوافذ استعراض وإضافة وتعديل وحذف الطلبات.

---

## تغطية متطلبات المهمة (Task #56 Checklist)
1. **عرض قائمة الطلبات:** رقم الطلب، اسم الزبون، تفاصيل المنتجات، المبلغ بالريال، التاريخ، وحالة الطلب (`جديد`، `في الطريق`، `تم التوصيل`) بشارات لونية واضحة.
2. **بيانات تجريبية واقعية (20+ طلب):** قاعدة بيانات محاكية (`src/constants/mockData.json`) تضم **24 طلباً** واقعياً عبر طبقة جلب شبكية تحاكي زمن استجابة الخادم (`src/lib/fetchClient.ts`).
3. **البحث والترتيب:** خانة بحث فورية باسم الزبون + قائمة وأزرار ترتيب صريحة حسب **التاريخ** (الأحدث / الأقدم) أو **المبلغ** (الأعلى / الأقل).
4. **حالات الواجهة الكاملة (UI States):**
   - حالة التحميل (`Loading`) مع رسالة واضحة وهياكل تحميل (`Skeleton`) مطابقة لتخطيط الصفحة.
   - حالة الخطأ (`Error`) مع زر **«إعادة المحاولة»** مربوط بـ `refetch()` + زر مدمج لاختبار حالة الخطأ مباشرة من الواجهة.
   - حالة الفراغ (`Empty`) عند عدم مطابقة البحث لأي طلب مع زر مسح البحث الفوري.
5. **العربية والتجاوب الكامل (`RTL & Responsive`):** تصميم عربي أصيل بخط `IBM Plex Sans Arabic` ودعم الوضعين الفاتح والداكن، مع تحول تلقائي للجدول إلى بطاقات طلبات مريحة على شاشة الجوال.

## التقنيات المستخدمة (Tech Stack)
- **إطار العمل والبناء:** `React 19` + `TypeScript` + `Vite 8`
- **التصميم ومكونات الواجهة:** `Tailwind CSS v4` + `Shadcn UI` (`RTL`) + `Motion`
- **التوجيه (Routing):** `React Router v7` مع التحميل الكسول للصفحات (`React.lazy` & `Suspense`)
- **جلب البيانات والتخزين المؤقت:** `TanStack Query v5` (`staleTime` لمحاكاة الكاش الحقيقي دون إعادة تحميل مزعجة عند التنقل)
- **الجداول والفرز والترقيم:** `TanStack Table v8` (`DataTable`)
- **النماذج والتحقق:** `React Hook Form` + `Zod`
- **الرسوم البيانية:** `Recharts`

## البنية المعمارية للمشروع (Project Structure)

```text
src/
├── app/                  # إعدادات التطبيق العامة (Providers, Router, Error Pages, CSS)
├── components/           # مكونات الواجهة المشتركة وتخطيط لوحة التحكم (Layout & UI)
├── constants/            # مسارات النظام وبيانات الـ API المحاكية (mockData.json)
├── features/             # تقسيم الميزات المستقلة (Feature-Based Architecture)
│   ├── landing/          # الصفحة التعريفية للمشروع ومقدم المهمة
│   ├── main/             # لوحة الإحصائيات والرسوم البيانية (`api`, `hooks`, `charts`, `components`, `pages`)
│   └── orders/           # نظام إدارة الطلبات (`api`, `hooks`, `components`, `pages`)
├── hooks/                # الـ Hooks المشتركة (Theme, Mobile Detection)
├── lib/                  # محاكي الشبكة (`fetchClient.ts`) ودوال التنسيق (`formater.ts`)
└── types/                # تعريفات الأنواع الصارمة (`Order`, `Dashboard`, `Api`)
```
